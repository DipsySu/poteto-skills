## 2. Keep declared routes named like filesystem roots (`/home`, SCIM's `/Users`), and read `store_true` options as flags, so drift_check judges the map against what the source declares

- Source: https://www.rfc-editor.org/rfc/rfc7644 https://docs.python.org/3/library/argparse.html
- Level: verification
- Skill: create-verification-skill
- Change: `scan_repo.py` is the inventory that scaffold.py maps and that maintain-verification-skill's drift_check.py compares against (drift_check.py:132). It misreads two common shapes, and drift_check's verdict goes wrong both ways.
  - Routes. `normalize_route()` returns `None` for any path under a filesystem root (`FS_PREFIX`, scan_repo.py:59, applied at :129): `/home`, `/dev`, `/private`, `/Users`, `/tmp`, and the rest. It does this for every caller, including route decorators (:340), Django `path()` (:361), handler comparisons (:457), and the Node and Go readers (:757, :787, :790). So `@app.get("/home")` or `if path == "/home":` drops out of the inventory:
    - the scaffold never maps it;
    - drift_check reports nothing when the map leaves it out;
    - when the map does list it, drift_check reports `route dead in map` (drift_check.py:174-179), which tells the maintainer to delete a live route.

    RFC 7644's SCIM endpoints show the case. Its Table 2 serves the User resource at `/Users`, so a SCIM server loses its main route while `/Groups` stays.
  - Flags. scan_repo records only `default=` for each `add_argument` option (scan_repo.py:369-374). drift_check treats every option whose default isn't a bool as taking a value (drift_check.py:189-191). A `store_true` option almost never spells out its default, because argparse supplies it: these actions "respectively store the values `True` and `False`" "with default values of `False` and `True`".
    - So `--json` counts as a value flag. In `python3 -m todo --json list`, the scan of flags before the subcommand (drift_check.py:123-125) takes `list` as `--json`'s value.
    - drift_check then reports `command missing from map: python3 -m todo list`, and `todo --json add milk` reports `milk` as a dead command.
    - argparse's own sub-commands example has this shape: `parser.parse_args(['--foo', 'b', '--baz', 'Z'])`, where `--foo` is a `store_true` flag before the subcommand `b`.

  The change:
  - `normalize_route(s, kind, declared=False)`. Callers that read a router registration, a route decorator, a route table, a `"GET /x"` string, or a path comparison pass `declared=True`, which skips `FS_PREFIX`. Only strings found in containers or generic call arguments keep the filter.
  - scan_repo records `takes_value` for each option. It is false for `action` store_true, store_false, store_const, append_const, count, help, and version, and for click's `is_flag=True` and `count=True`. drift_check.py:190 reads `takes_value` instead of guessing from the default.

  Add run_examples assertions to `maintain()` (run_examples.py:463):
  - Add a `/home` branch to the scratch app's GET handler, the way the `/metrics` case does (run_examples.py:482-484). Today drift_check exits 0 and lists nothing. After, it reports `GET /home` missing, and a feature file that maps `GET /home` isn't reported dead.
  - Add a top-level `parser.add_argument("--json", action="store_true")` to the scratch `todo/__main__.py`, and write the list recipe as `python3 -m todo --json list`. Today drift_check reports `list` missing. After, it is clean.
  - A `/tmp/...` string passed only to a generic call is still not a route.
- Why: The route scanner throws away declared routes such as `/home` and SCIM's `/Users` because they look like filesystem paths, and it reads every `store_true` flag as taking a value, so drift_check passes a map that leaves a live page out, reports a correct map entry as dead, and reports a mapped subcommand as missing.

## 4. Give `gen_check.py` and `bounded_check.py` a time limit per call and per run, report hitting it as inconclusive (exit 3) with the input or state, and stop `filter_too_much` from overwriting a result

- Source: https://github.com/model-checking/kani/blob/49a7a03905b5e676e6a4796caf114169a7ae6ad0/agent-plugin/skills/verify-rust/SKILL.md https://github.com/model-checking/kani/blob/49a7a03905b5e676e6a4796caf114169a7ae6ad0/agent-plugin/scripts/guarded-run.py https://hypothesis.readthedocs.io/en/latest/reference/api.html
- Level: verification
- Skill: formal-verification
- Change: Neither checker limits how long a call or a run may take.
  - `gen_check.py` calls `check(value)` with no limit (gen_check.py:249), and prints everything, seed included, only at the end (lines 338-352). A property over code that loops never returns, and the run prints nothing, not even the seed that would replay it.
    - For example, take a scratch `todo/text.py` whose `strip_leading(t)` loops on `while i < len(t) and t[i] == " ": pass`, with the `i += 1` missing.
    - Checked as `strip_leading(t) == t.lstrip(" ")` over `text(" ab", max_size=8)`, it hangs on the first input that starts with a space.
  - `bounded_check.py` calls `actions_fn(s)` with no limit (bounded_check.py:152). A model whose `actions()` busy-waits on a state hangs the same way, and the run never reaches its report.
  - The agent's shell kills such a run when its tool call times out, and the result is lost. Kani's draft agent plugin (kani#5059, at `49a7a03`, pushed 2026-11-07) tells agents to "give every run a limit", because shell tools have a "2 to 10 minute limit". It says "A TIMEOUT or OUT_OF_MEMORY verdict is not a failure and not a proof", and its `guarded-run.py` gives a killed run an "export with `run_state` KILLED or TIMEOUT, so the result is not lost."
  - Two results in `run_property()` are wrong today as well:
    - `attempt()` catches `BaseException` (gen_check.py:252), so a Ctrl-C during a check is recorded as a counterexample, and `--expect-fail` accepts it.
    - The rejection limit (lines 299-300) runs after the loop stops at a failure, and it overwrites that failure. Two rejections and then a failing input give 2 × 2 > 3, so the result is `filter_too_much` and `--expect-fail` (lines 330-332) exits 1 on a seed that caught the break. Our `filter_too_much` copies a Hypothesis health check, and Hypothesis's API reference says "A health check is a proactive warning, not an error". It says its health checks "warn about performance problems, not correctness errors".

  The change:
