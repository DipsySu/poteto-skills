  - `WORKAROUND_RE` (mine_mistakes.py:58) is only HACK, WORKAROUND, FIXME, and XXX. A comment like `# for now, write the file directly` or `// temporary fix until the lock is faster` never becomes a signal.

  The change:
  - Add `references/excuse-comments.json`, a patlint rules file with one rule, `no-excuse-comment`.
    - `include` lists source files (`**/*.py`, `**/*.js`, `**/*.ts`, `**/*.go`, `**/*.rs`, `**/*.sh`, and so on), not Markdown, and `ignore_case` is on.

It expects `ok` on `# TODO(#42): move retries into Store.add`, on mine_mistakes.py:665's `ap.add_argument("--no-code-comments", action="store_true", help="skip HACK/WORKAROUND/FIXME/XXX comments")`, and on :58's `WORKAROUND_RE = r"\b(HACK|WORKAROUND|FIXME|XXX)\b"`.

It takes `git grep -i -E` hits as candidates and keeps only the lines the rule's regex matches, so mining and the lint share one pattern. collect_feedback.py:76 gets it through the same function. That's correct/SKILL.md:36's "one source of truth instead of hand-synced lists".
  - correct/SKILL.md section 3 gains one line: copy `no-excuse-comment` into the project's lint-rules.json, run `$P --test`, and adopt it once with `--update-baseline .`. Existing excuse comments then sit in the baseline, and new ones fail.
